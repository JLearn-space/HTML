## Блок 1. Планирование  прежде чем писать код

**Простыми словами:** прежде чем строить дом, архитектор рисует план на бумаге — сколько комнат, что где расположено, как перемещаться между ними. С сайтом то же самое: если сесть писать код без плана, велик риск постоянно всё переделывать на ходу.

### Шаг 1. Выберите тему проекта

Итоговый проект - это простой многостраничный сайт-визитка. Примеры хороших тем для учебного проекта:

- Личное портфолио (о себе, проекты, контакты).
- Сайт небольшого локального бизнеса (кафе, репетиторство, мастерская).
- Сайт-визитка учебного курса или клуба по интересам.

**Важно:** выбирайте тему, в которой у вас реально есть что рассказать — так будет проще наполнить страницы содержательным, а не "текстом для галочки" контентом.

### Шаг 2. Определите структуру страниц (карта сайта)

Пропишите на бумаге или в текстовом файле список страниц и что на каждой из них будет:

**Пример карты сайта для личного портфолио:**

|Страница|Файл|Содержимое|
|---|---|---|
|Главная|`index.html`|Приветствие, краткое "о себе", ссылки на остальные разделы|
|О себе|`about.html`|Развёрнутый рассказ, фото, список навыков|
|Проекты|`projects.html`|Список работ с изображениями-превью|
|Контакты|`contact.html`|Форма обратной связи, таблица со способами связи|

### Шаг 3. Составьте план содержимого для каждой страницы

Для каждой страницы кратко пропишите, какие HTML-инструменты из курса вы будете использовать. Например, для `contact.html`:

- `<header>` со сквозным меню `<nav>`
- `<main>` с заголовком `<h1>Контакты</h1>`
- `<table>` со `scope` — способы связи и время работы
- `<form>` с `fieldset`/`legend` — форма обратной связи
- `<footer>` со ссылками на соцсети через `aria-label`

**Это планирование - не формальность.** Именно на этом шаге вы обычно замечаете нестыковки: например, что на главной странице нет ссылки на страницу, которую вы только что придумали, - гораздо проще исправить это на бумаге, чем после того, как уже написан код четырёх страниц.

## Блок 2. Пошаговая сборка: семантика (скелет каждой страницы)

Начинаем сборку с семантического скелета - того, что мы разбирали в уроке 2. Это делается **до** наполнения реальным содержимым - сначала структура, потом контент внутрь неё.

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title><!-- заполним в блоке 7 --></title>
</head>
<body>
    <header>
        <nav>
            <!-- сквозное меню -->
        </nav>
    </header>

    <main>
        <!-- основной контент страницы -->
    </main>

    <footer>
        <!-- подвал -->
    </footer>
</body>
</html>
```

**Сделайте это для каждой страницы вашего проекта одинаково** - единый скелет с одинаковым `<header>`/`<nav>`/`<footer>` на всех страницах, отличается только содержимое `<main>` - именно так мы уже делали многостраничный сайт в уроке 3.

## Блок 3. Пошаговая сборка: контент (текст, заголовки, списки)

Теперь наполняем `<main>` реальным текстом, используя правильную иерархию заголовков (урок 2) - единственный `<h1>` на странице, без пропуска уровней.

**Пример для `about.html`:**

```html
<main>
    <h1>Обо мне</h1>

    <p>Меня зовут Азиз, и я <strong>увлечён веб-разработкой</strong> уже больше года. Начал с HTML — и вот прохожу этот курс, чтобы упорядочить свои знания.</p>

    <h2>Мои навыки</h2>
    <ul>
        <li>HTML5 — семантическая вёрстка</li>
        <li>Базовые основы CSS</li>
        <li>Изучаю JavaScript</li>
    </ul>

    <h2>Мой путь</h2>
    <ol>
        <li>Начал изучать вёрстку самостоятельно</li>
        <li>Прошёл курс «HTML: от А до Я»</li>
        <li>Планирую двигаться дальше — к CSS и JavaScript</li>
    </ol>
</main>
```

Используйте `<strong>`/`<em>` там, где текст действительно требует смыслового акцента - не для украшения, а для содержания (как мы разбирали в уроке 2).

## Блок 4. Пошаговая сборка: медиа (изображения)

Добавьте изображения там, где они уместны - фото профиля, превью проектов, иллюстрации. Не забывайте про `alt` (урок 4) и `figure`/`figcaption`, если изображению нужна подпись.

```html
<figure>
    <img src="images/profile-photo.jpg" alt="Азиз улыбается на фоне ноутбука с открытым кодом" width="300">
    <figcaption>Моё рабочее место</figcaption>
</figure>
```

**Если у вас нет собственных фотографий для проекта** - используйте свободные изображения-заглушки (важно всё равно писать содержательный `alt`, соответствующий тому, что реально изображено на картинке, а не выдуманный текст).

---

## Блок 5. Пошаговая сборка: таблица

Добавьте таблицу там, где в проекте реально есть табличные данные (урок 5) — помните правило: таблица только для данных, не для вёрстки макета.

**Пример для `contact.html` - таблица способов связи:**

```html
<table>
    <caption>Способы связи</caption>
    <thead>
        <tr>
            <th scope="col">Способ</th>
            <th scope="col">Контакт</th>
            <th scope="col">Время ответа</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <th scope="row">Email</th>
            <td><a href="mailto:info@saydullayev.fun">info@saydullayev.fun</a></td>
            <td>В течение суток</td>
        </tr>
        <tr>
            <th scope="row">Telegram</th>
            <td><a href="https://t.me/example" target="_blank" rel="noopener noreferrer">@example</a></td>
            <td>Несколько часов</td>
        </tr>
    </tbody>
</table>
```

**Если для вашей темы проекта таблица неуместна** (например, чисто визуальное портфолио без сравнительных данных) - это нормально, не добавляйте таблицу искусственно только ради использования тега. Используйте свою инженерную оценку: тег должен появляться там, где он решает реальную задачу.

## Блок 6. Пошаговая сборка: форма

Добавьте форму обратной связи (урок 6-7), с правильной связкой `label`/`for`/`id`, группировкой через `fieldset`/`legend`, и хотя бы минимальной валидацией.

```html
<form action="#" method="post">
    <fieldset>
        <legend>Свяжитесь со мной</legend>

        <label for="name">Имя:</label>
        <input type="text" id="name" name="name" required maxlength="50"><br>

        <label for="email">Email:</label>
        <input type="email" id="email" name="email" required><br>

        <label for="message">Сообщение:</label><br>
        <textarea id="message" name="message" rows="5" cols="40" placeholder="Напишите ваш вопрос..." required></textarea>
    </fieldset>

    <button type="submit">Отправить</button>
</form>
```

**Напоминание из урока 6:** `action="#"` - это заглушка, так как у нас нет серверной обработки в этом курсе; главное - правильная структура и доступность самой формы.

## Блок 7. Пошаговая сборка: мета-теги

Заполните `<head>` каждой страницы (урок 9) — теперь, когда контент уже готов, легко написать содержательный `description`.

```html
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <meta name="description" content="Обо мне — Азиз, начинающий веб-разработчик, изучающий HTML, CSS и JavaScript.">
    <title>Обо мне — Портфолио Азиза</title>
    <link rel="icon" type="image/png" href="favicon.png">
    <link rel="stylesheet" href="css/style.css">
</head>
```

**Проверьте на каждой странице:** уникальный `<title>` (не одинаковый на всех страницах!), уникальный `description`, отражающий именно содержимое конкретной страницы.

## Блок 8. Пошаговая сборка: доступность

Финальная проверка каждой страницы по инструментам урока 8:

- Все `<img>` имеют осмысленный `alt` (или пустой `alt=""` для декоративных изображений).
- Иконки-ссылки без текста имеют `aria-label`.
- Иерархия заголовков не имеет пропусков и единственного `<h1>` на странице.
- Проверьте Tab-навигацию — дойдите до каждого интерактивного элемента без мыши.

## Блок 9. Финальный чек-лист качества

Пройдите по этому списку для **каждой** страницы вашего проекта — отмечайте прямо на бумаге или в заметках:

- [ ] Единственный `<h1>` на странице
- [ ] Семантика вместо div-супа (`header`/`nav`/`main`/`footer` используются по назначению)
- [ ] `alt` у всех `<img>`
- [ ] `label` у всех полей формы
- [ ] Осмысленный текст ссылок (не "нажмите тут", а понятное описание — например, "Читать подробнее о проекте")
- [ ] `meta charset` и `meta viewport` на месте
- [ ] Код проходит W3C-валидацию без ошибок
- [ ] Страница читаема на мобильном экране (можно проверить через DevTools — режим устройства, иконка телефона/планшета в верхней панели)

**Пройдите этот чек-лист прямо сейчас по одной из ваших готовых страниц** — скорее всего, найдётся хотя бы один пункт, который стоит доработать. Это нормально и полезно — именно так выглядит настоящая проверка качества перед публикацией.

## Блок 10. Публикация на GitHub Pages

Финальный шаг курса - сделать ваш сайт доступным всему миру по реальной ссылке, а не только на вашем компьютере.

### Что такое GitHub Pages

GitHub - сервис для хранения кода (мы упоминали его как площадку для портфолио в предыдущих уроках). **GitHub Pages** - бесплатная функция GitHub, которая позволяет опубликовать статический HTML/CSS/JS-сайт прямо из вашего репозитория по адресу вида `username.github.io/repository-name`.

### Пошаговая инструкция

**Шаг 1.** Если у вас ещё нет аккаунта на GitHub — зарегистрируйтесь на github.com.

**Шаг 2.** Создайте новый репозиторий:

- Нажмите "New repository".
- Дайте название, например `my-portfolio`.
- Выберите "Public" (репозиторий должен быть публичным для бесплатного GitHub Pages).
- Нажмите "Create repository".

**Шаг 3.** Загрузите файлы проекта одним из двух способов:

_Способ А — через веб-интерфейс (проще для новичков):_

- На странице репозитория нажмите "uploading an existing file".
- Перетащите все файлы и папки вашего проекта (`index.html`, `css/`, `js/`, `images/` и т.д.).
- Внизу нажмите "Commit changes".

_Способ Б — через Git из терминала (если вы уже знакомы с Git):_

```bash
git init
git add .
git commit -m "Первая публикация сайта"
git branch -M main
git remote add origin https://github.com/ваш-username/my-portfolio.git
git push -u origin main
```

**Шаг 4.** Включите GitHub Pages:

- Откройте вкладку "Settings" в вашем репозитории.
- В боковом меню найдите раздел "Pages".
- В разделе "Source" выберите ветку `main` и папку `/ (root)`.
- Нажмите "Save".

**Шаг 5.** Подождите 1-2 минуты — GitHub соберёт и опубликует ваш сайт. Обновите страницу настроек "Pages" — там появится ссылка вида:

```
https://ваш-username.github.io/my-portfolio/
```

**Шаг 6.** Откройте эту ссылку в браузере — ваш сайт теперь доступен любому человеку в интернете.

### Важный практический момент: имя главного файла

GitHub Pages автоматически открывает файл `index.html` при заходе на корневой адрес репозитория — поэтому важно, чтобы ваша главная страница называлась именно `index.html` (а не, например, `home.html` или `main.html`), иначе по короткой ссылке она не откроется автоматически.

### Обновление сайта в будущем

Если позже вы захотите что-то поменять — просто загрузите обновлённые файлы тем же способом (через веб-интерфейс "Add file" → "Upload files", либо `git push`, если работаете через терминал) — GitHub Pages автоматически пересоберёт и обновит опубликованную версию сайта в течение пары минут.

---

###  Частые ошибки при публикации

|Ошибка|Как исправить|
|---|---|
|Репозиторий создан приватным (Private)|Для бесплатного GitHub Pages репозиторий должен быть публичным|
|Главная страница названа не `index.html`|Переименуйте файл главной страницы именно в `index.html`|
|Пути к CSS/JS/картинкам ломаются после публикации|Убедитесь, что используете относительные пути (урок 3), а не абсолютные пути вида `C:\Users\...`, которые работают только на вашем компьютере|
|Не включена сама функция Pages в настройках|Не забудьте зайти в Settings → Pages и явно выбрать ветку публикации|
